Lab 2

Compliance Evidence & Guardrails

Module 2 — Security OF the Cloud

🎯 Objective

  • Answer an auditor's evidence requests by finding the real evidence pages in the AWS console
  • Decide which evidence AWS provides (inherited controls in AWS Artifact) and which you must produce yourself
  • Review a "locked-down" Service Control Policy, write the guardrails it should contain, and check them with the IAM policy validator

👥 Shared class account: everyone works in the same AWS account. Start every resource name with your student ID, and only open, change, or delete resources that start with your ID.

📚 Terms You'll See

  • AWS Artifact — console portal for AWS compliance reports (SOC, ISO, PCI) and agreements (BAA)
  • Inherited control — a control AWS operates that you rely on, evidenced by AWS's reports
  • AWS Health — dashboard of AWS-side events affecting your account and services
  • Credential report — IAM-generated CSV listing every IAM user, MFA status, and password/key age
  • CloudTrail Event history — 90 days of management events, recorded in every account with no setup
  • AWS Organizations — groups accounts into OUs under one management account
  • OU (Organizational Unit) — folder of accounts that policies attach to
  • SCP (Service Control Policy) — sets the maximum permissions for every principal in an account, including its admins
  • Policy validator — IAM Access Analyzer checks run live in the IAM JSON policy editor

⚙️ Before You Start

  • Sign in to the class AWS account and set the region selector to US East (N. Virginia) us-east-1
  • This lab creates no AWS resources (generating the credential report is the only change, and it is logged)
  • Shared class account rule: you will write SCPs and validate them only — never create, attach, or edit SCPs or any AWS Organizations setting; that would affect every account in the organization
  • AWS Config, Security Hub, and Audit Manager are not enabled in the class account; treat them as written answers only
  • In AWS Artifact, do not accept terms or download reports unless your instructor says to

Requests 1, 4, and the AWS half of 6

  3. In the search box, type SOC 2
  4. Choose System and Organization Controls (SOC) 2 Report and read its description and the period it covers

  6. Clear the search, type ISO 27001, and note the ISO 27001:2022 Certification report

✅ Check: the SOC 2 description reads "The AWS SOC 2 Type 2 report evaluates the AWS controls…" for security, availability, confidentiality, and privacy, covering a 12-month period. All three reports are in the Certifications and Attestations category.

👤 Task 1c — Your Side: Who Has Admin?

Request 5

  1. Open IAM. In the left navigation, under Access reports, choose Credential report
  2. Choose Download credentials report and open the CSV
  3. Find the mfa_active, password_last_used, and access_key_1_last_rotated columns
  4. In the left navigation, choose Policies and search for AdministratorAccess
  5. Open the AWS managed policy AdministratorAccess and choose the Entities attached tab

✅ Check: the CSV starts with a <root_account> row followed by one row per IAM user. IAM reuses a report for up to 4 hours, so users created since then are not listed yet. Entities attached lists every user, group, and role that has full admin access.

📜 Task 1d — Your Side: Admin Activity Log

Request 3

  1. Open CloudTrail. In the left navigation, choose Event history
  2. In the lookup attribute dropdown (default Read-only), choose Event source
  3. Enter iam.amazonaws.com and apply the filter
  4. Find the GenerateCredentialReport event you triggered in Task 1c (classmates' calls appear too, so match the User name column to your sign-in name), then open it to see who called it, from which IP address, and when

✅ Check: your own GenerateCredentialReport and GetCredentialReport calls appear (IAM events are logged in us-east-1). Events typically appear within about 5 minutes (not guaranteed), so refresh if needed.

Event history keeps only 90 days and needs no trail. For audit-grade, long-term evidence, PayLane needs a CloudTrail trail delivered to a central log-archive account.

🔐 Task 1e — Your Side: Encryption & Patching

Requests 2 and 6

  1. Open EC2. In the left navigation, choose Settings, then the Data protection and security tab
  2. Read the EBS encryption panel. Do not choose Manage
  3. Open Systems Manager. In the left navigation, choose Patch Manager
  4. If a landing page appears, choose View dashboard; then open the Patch baselines tab and find AWS-AmazonLinux2023DefaultPatchBaseline

✅ Check: Always encrypt new EBS volumes shows Disabled unless your instructor turned it on. Encryption is a setting you own. The AWS-provided baselines are listed, and the Amazon Linux 2023 baseline is marked as the default. With no managed instances, there is no patch compliance data yet.

For RDS, the evidence is the Encryption field on each database's Configuration tab, or an AWS Config rule such as rds-storage-encrypted.

✅ Task 1 — Sample Answer

  • 1 — AWS: SOC 2 report in AWS Artifact (physical and environmental security controls)
  • 2 — PayLane: RDS Configuration tab / EBS encryption setting. At scale, the AWS Config rule rds-storage-encrypted or Audit Manager evidence
  • 3 — PayLane: CloudTrail. Event history covers 90 days, and a trail to a central log-archive account provides long-term, tamper-resistant evidence
  • 4 — AWS: SOC 2 / ISO 27001 reports in Artifact (media sanitization and decommissioning controls)
  • 5 — PayLane: IAM credential report, Entities attached on admin policies, and IAM Identity Center assignments, plus your own access-review records
  • 6 — Both: AWS patches the hypervisor and hardware (Artifact). PayLane patches the guest OS (Patch Manager baselines and compliance)
  • 7 — Both: AWS publishes the events (Health Event log). PayLane shows it reviewed and responded (tickets, runbooks)

Rule of thumb: AWS gives you evidence for its side of the line, and you produce the evidence for yours. A SOC report covers a past period, so ask for the Continued Operations Letter (bridge letter) to cover the gap until today.

📜 Task 2 — Review This SCP

Attached to the Production OU. The security lead says it "locks down prod." List at least three problems.

{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "AllowEverything",
      "Effect": "Allow",
      "Action": "*",
      "Resource": "*"
    },
    {
      "Sid": "ProtectLogging",
      "Effect": "Deny",
      "Action": "cloudtrail:DeleteTrail",
      "Resource": "*"
    }
  ]
}

⚠️ Task 2 — Issues

  • AllowEverything is the same as the default FullAWSAccess SCP — it adds no restriction
  • Only DeleteTrail is denied — an attacker can still run StopLogging, UpdateTrail, or PutEventSelectors to blind you
  • Nothing stops an account from leaving the organization (organizations:LeaveOrganization) to escape the guardrails
  • No region restriction — resources can be created in regions nobody monitors
  • Nothing protects GuardDuty, Config, or Security Hub from being disabled
  • Nothing restricts the root user of member accounts

✏️ Task 3 — Write the Guardrails

Write Deny statements for an SCP that does the following. Use the hints only if you get stuck.

  1. Prevent anyone from stopping, deleting, or changing CloudTrail trails
  2. Prevent member accounts from leaving the organization
  3. Block all actions outside us-east-1 and us-west-2
  4. Prevent GuardDuty detectors from being deleted or disabled

Hints: the region key is aws:RequestedRegion. Global services such as IAM, Organizations, and Support are served from us-east-1, so a region deny must exempt them with NotAction. Use aws:PrincipalARN with ArnNotLike to exempt a security role named SecurityAutomation.

🧪 Task 3 — Validate Your Guardrails

The class account is the organization's management account: never create or attach an SCP here. The IAM policy editor runs IAM Access Analyzer checks on any JSON policy, so you can validate without saving anything.

  1. Open IAM → Policies → Create policy
  2. In the Policy editor, choose JSON and replace the contents with your Task 3 Deny statements
  3. Read the counts below the editor: Security, Errors, Warnings, Suggestions. Open each finding
  4. Fix any errors, then confirm all four counts show 0
  5. Now replace the contents with the flawed Task 2 SCP and read the findings
  6. Choose Cancel. Do not choose Next

Stuck? Paste the sample solutions from the next slides. Both show 0 findings.

✅ Check — What the Validator Reports

Policy pastedFindings you should see

Typo such as cloudtrail:StopLogingError: Invalid action ("The action cloudtrail:StopLoging does not exist.")

The validator checks grammar, not intent. "Action": "*" denied outside two regions validates with 0 findings, yet it would break IAM, Organizations, and Support. That's why the sample uses NotAction. The two Task 2 findings are identity-policy checks; validated as an SCP, the same JSON shows 0 findings.

✅ Task 3 — Sample Solution (1 of 2)

Protect logging, threat detection, and org membership. The ArnNotLike condition exempts one locked-down security role so the security team can still manage these services.

{
  "Version": "2012-10-17",
  "Statement": [
    { "Sid": "ProtectCloudTrail", "Effect": "Deny",
      "Action": ["cloudtrail:StopLogging", "cloudtrail:DeleteTrail",
                 "cloudtrail:UpdateTrail", "cloudtrail:PutEventSelectors"],
      "Resource": "*",
      "Condition": { "ArnNotLike": {
        "aws:PrincipalARN": "arn:aws:iam::*:role/SecurityAutomation" } } },
    { "Sid": "ProtectGuardDuty", "Effect": "Deny",
      "Action": ["guardduty:DeleteDetector", "guardduty:UpdateDetector",
                 "guardduty:DisassociateFromAdministratorAccount",
                 "guardduty:DisassociateFromMasterAccount"],
      "Resource": "*",
      "Condition": { "ArnNotLike": {
        "aws:PrincipalARN": "arn:aws:iam::*:role/SecurityAutomation" } } },
    { "Sid": "StayInOrg", "Effect": "Deny",
      "Action": "organizations:LeaveOrganization", "Resource": "*" }
  ]
}

✅ Task 3 — Sample Solution (2 of 2)

Region allow-list. The NotAction list is AWS's published set of global services that must stay reachable from any region (source: AWS service-control-policy-examples repository).

{
  "Version": "2012-10-17",
  "Statement": [
    { "Sid": "RegionAllowList", "Effect": "Deny",
      "NotAction": [
        "a4b:*", "acm:*", "aws-marketplace-management:*", "aws-marketplace:*",
        "aws-portal:*", "budgets:*", "ce:*", "chime:*", "cloudfront:*", "config:*",
        "cur:*", "directconnect:*", "ec2:DescribeRegions", "ec2:DescribeTransitGateways",
        "ec2:DescribeVpnGateways", "fms:*", "globalaccelerator:*", "health:*", "iam:*",
        "importexport:*", "kms:*", "mobileanalytics:*", "networkmanager:*",
        "organizations:*", "pricing:*", "route53:*", "route53domains:*",
        "route53-recovery-cluster:*", "route53-recovery-control-config:*",
        "route53-recovery-readiness:*", "s3:GetAccountPublic*", "s3:ListAllMyBuckets",
        "s3:ListMultiRegionAccessPoints", "s3:PutAccountPublic*", "shield:*", "sts:*",
        "support:*", "trustedadvisor:*", "waf-regional:*", "waf:*", "wafv2:*",
        "wellarchitected:*"
      ],
      "Resource": "*",
      "Condition": {
        "StringNotEquals": { "aws:RequestedRegion": ["us-east-1", "us-west-2"] },
        "ArnNotLike": { "aws:PrincipalARN": "arn:aws:iam::*:role/SecurityAutomation" } } }
  ]
}
